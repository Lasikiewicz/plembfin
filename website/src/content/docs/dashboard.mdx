The Dashboard separates three kinds of information that are easy to confuse: what is
playing now, what is ready to continue next, and completed watch history.

The Up Next queue can contain both movies and TV episodes. Resume progress is part of that
queue; it is not a separate history rail.

The sections are independent, so the same title can appear in live playback, Up Next, and
the durable archive when each state is valid.

Live changes are reconciled against the affected cards, so unchanged dashboard
cards keep their artwork and layout while another title updates. A cleared resume item is
hidden immediately and stays dismissed while provider data catches up; if the clear fails,
the item is restored.


## Page structure

The sidebar opens the main pages.

The Dashboard content is arranged in this order:

1. **Now Playing** for active media-server sessions.
2. **Up Next** for movie and TV continuation items, including saved resume progress and
   released episodes selected from tracked shows.
3. **TV Shows – Recently watched** for recent completed TV watches.
4. **Movies – Recently watched** for recent completed movie watches.

If there is no saved resume progress or next-up item, Up Next is omitted. The sidebar
**Sync** indicator is a shortcut to [Sync Activity](/docs/sync-tools/).

Dashboard history uses **Card View** by default. The Dashboard has no separate Appearance
layout control.

## Global Search

<ScreenshotFigure
  darkSrc="/assets/app-captures/global-search-dark.png"

Global Search belongs to the persistent Dashboard controls, not to the History archive. Open
the search field in the left sidebar, enter a title, person, provider ID, or collection name,
then choose the result type when you need a narrower match.

Local titles are prioritised and marked when they already exist in the archive. A movie or show
opens its normal detail page; a person opens the person page. Search finds and explores titles,
while watch-state corrections stay on the selected local title's actions.

## Now Playing

Now Playing is session information, not completed watch history.

It can show the title, season and episode, source service, current position, duration, and
a progress bar for active sessions reported by Plex, Emby, or Jellyfin.

<ScreenshotFigure
  darkSrc="/assets/app-captures/now-playing-dark.png"
  lightSrc="/assets/app-captures/now-playing-light.png"
  alt="Plembfin Now Playing section showing active playback sessions and progress"
  caption="Each session identifies its source and current playback position."
/>

To use it:

1. Start or resume a title in a connected media server.
2. Return to the Dashboard while playback is active.
3. Check the source badge, position, and duration.
4. Select the title to open its media details when you need more actions.

Plembfin refreshes active sessions independently of the normal scheduled sync: the poll is
more frequent while something is playing, and opening the Dashboard or returning to a
background tab requests a fresh snapshot immediately.

A provider failure is kept separate from a genuinely empty session result, so a temporary
connection problem does not falsely report that playback stopped. Disappearing from Now
Playing does not, by itself, create a completed watch.

Completed playback and sessions beyond the active-session window are removed from Now Playing,
so stale cards do not linger after playback stops.

If a session never appears, follow
[Now Playing is empty or stale](/docs/troubleshooting/#now-playing-is-empty-or-stale).

## Up Next

<ScreenshotFigure
  darkSrc="/assets/app-captures/dashboard-up-next-dark.png"
  lightSrc="/assets/app-captures/dashboard-up-next-light.png"
  alt="Plembfin dashboard Up Next row showing current resume cards with provider Watch now links"
  caption="Up Next presents the current continuation queue with provider availability and Watch now links."
/>

Up Next is the dashboard's mixed continuation rail. It combines actionable resume records
for movies and episodes with released **next up** episodes from tracked shows. Resume cards
are ordered by their latest progress update; next-up cards follow with deterministic show,
season, and episode ordering.

Each card can show its real episode name, season and episode code, air-date context, resume
state, and the media servers where it is available. **Watch Now** links open a matching
item in Plex, Emby, or Jellyfin when a connected server can provide one. A cached local
resume card remains useful without a provider connection.

When **Sync Up Next to media apps** is enabled in [Settings → Sync → Sync tuning](/docs/settings/sync/#sync-tuning),
Plembfin queues one coalesced background push whenever the unified queue changes. Additions,
reorderings, and resume-progress changes are sent to Plex Continue Watching, Emby Continue
Watching, and Jellyfin Next Up. The push never removes an item just because Plembfin's queue
does not list it: an item leaves a media app only when you clear its progress or remove it in
Plembfin, and the sync message reports how many app-only items were left in place. The worker
uses the latest queue and continues even when the Dashboard is closed. Use **Sync Up Next** for
an explicit immediate push; turning the setting off leaves those provider lists unchanged while
Plembfin's own Up Next view remains available.

If a provider feed fails, Plembfin keeps the last good observation and shows a compact
source-status message instead of deleting the queue. An offline server is skipped by the push
and a new push is queued as soon as it answers again. The builder deduplicates matching resume
and next-up observations, keeps shows that share a title but have different TMDB or TVDB ids
as separate cards, and does not merge a re-release or reboot from a different year.

Use the card's **More options** menu for **Mark Watched**, **Rate**, **Add to watch list**,
**Clear Progress** when resume exists, or **Remove from Up Next**. Removing a card updates
the local rail immediately and attempts to clear the connected-app resume state through the
provider endpoint when that target is available. Marking watched commits locally first and
then dispatches through the normal sync path.

### Dismiss and restore an Up Next item

**Remove from Up Next** is the dismissal action. After you confirm it, Plembfin hides the card
immediately, clears its local resume progress, marks it unwatched, and records the dismissal on
the server. The dismissal therefore applies to the same account on every device rather than only
the browser where it was made. Plex Continue Watching and Emby Resume also receive a native
removal when the matching item is available; Jellyfin Next Up is a calculated feed with no
per-item removal endpoint, so Plembfin keeps the local queue authoritative while that feed catches
up.

When one or more items are dismissed, the count button beside the **Up Next** heading opens
**Dismissed Up Next**, which shows up to six cards per row on wide screens. Choose **Add back** for one item or **Add all back** to restore the cards;
Plembfin then pushes the restored queue to the connected media apps. A dismissal is a “not now”
choice, not a permanent delete: the item can return automatically after newer genuine playback
progress is recorded.

Resume progress lives in **Up Next**. A resume card appears while its progress has not crossed
the configured watched threshold and keeps the actions needed to decide what happens next:

- **Watch Now** or **Resume** opens the title so playback can continue in the connected media service.
- **Clear Progress** removes the resume marker without marking the title watched.
- **Mark Watched** records a completed watch and sends it through the normal sync path.

The card's More options menu also exposes the personal rating, watchlist, and removal actions.

The watched threshold and minimum resume position are controlled by
[Sync Tuning](/docs/settings/sync/#sync-tuning).

Changing those values affects how future playback is interpreted. For an incorrect percentage,
follow [Up Next resume progress is missing or wrong](/docs/troubleshooting/#up-next-resume-progress-is-missing-or-wrong).

## TV and movie history

The bottom rows are the recent durable completed-watch archive.

They are not a list of active files on a media server.

A title appears after Plembfin has recorded a watch event.

- The **TV Shows** row groups recent episode activity by show.
- The **Movies** row lists recent movie watch activity.
- A rewatch remains a separate event in History while the library card remains one title.
- Selecting a poster opens the media detail page.

An item can appear in Up Next with resume progress and also in completed history when it has
a previous watch.

## Dashboard history cards

Dashboard TV and movie history rows always use Card View. Each card combines the poster,
title, watch information, and state in a compact layout.

The Dashboard view is fixed; use the [Movies media page](/docs/movies/media-page/) or
[TV Shows media page](/docs/tv-shows/media-page/) for library-specific poster, list, and
overview controls. Appearance is available on those media detail pages for optional
content sections.

## A useful daily check

After a watch or a manual correction, read the Dashboard first.

Then open the newest row in [Sync Activity](/docs/sync-tools/) if a destination needs an
explanation.

The Dashboard is the summary.

Sync Activity is the evidence for each destination.
