Database Repairs Help

Database Care
Repair History Rows

Checks your 300 most recent history rows for a missing media type or poster.

If the type is missing, it's guessed from the title (like S01E01 for an episode). A poster is then found from the cache, your media server, or TMDB.

Works in small batches of 10 rows, and stops on its own once a batch finds nothing left to fix.

Audit Phantom Watches

Read-only scan for suspicious duplicate watches or broken imported episode data.

Each result is marked high-confidence or review-only. Nothing is changed or deleted - it's just a report.

Remove Duplicate Watches

Finds every movie or episode with more than one watch recorded, and keeps only the oldest date.

The rest are deleted for good, and the correction is pushed out to every connected platform.

You'll always see the exact number of watches affected before confirming. This cannot be undone.

Restore Missing Episode Names

Looks at watch history for TV episodes whose stored episode name is missing or is just a coordinate (such as 8 or Episode 08).

Audit is read-only and scans the full watch history. Restore fills in the real name using other stored rows and cached season metadata first, then a metadata lookup when needed. Episodes verified by the metadata source to have no title are reported separately as No title provided; only retryable failures remain for another attempt.

Wipe Data Help

Irreversible
What stays untouched

Your settings, media server connections, Trakt connection, API keys, and admin login are never touched by Watch History, Personal Watchlist, Sync History & Logs, or Everything Tracked.

Wipe All / Fresh Start is the one exception below - it resets those too.

Wiping local data does not unwatch anything on Plex, Emby, or Jellyfin themselves - it only clears what Plembfin has recorded.

Watch History

Deletes every watched item, resume position, and live session Plembfin has recorded. This is the same data a watch-history backup restores from - back one up first if you want a way back.

Personal Watchlist

Deletes the canonical local watchlist, mutation/tombstone history, provider observations, queued work, sync runs, activity, and Plembfin-owned playlist/container identifiers. It does not remove items from Plex, Emby, or Jellyfin.

Sync History & Logs

Deletes the sync history list, audit trail, and diagnostic logs. Lower stakes - your actual watch history is untouched.

Everything Tracked

Runs Watch History, Personal Watchlist, and Sync History & Logs together. Your settings and connections still stay untouched.

Wipe All / Fresh Start

The most destructive option here. Deletes everything above, plus settings, media server and Trakt connections, cached artwork, and the admin login.

Plembfin ends up exactly like a brand-new install - you'll be signed out and taken to first-run setup to claim the account again. A full Plembfin backup is the only way back.

Backup Guide

Disaster Recovery
Local Watch History Backups

Daily snapshots of watched state, playstate, and resume progress. Saved unencrypted to data/backups/watch-history on the server.

No passphrase needed. "Save Schedule" and "Back Up Now" work as soon as backups are enabled.

Local Plembfin Backups

A full encrypted export of the database and saved settings, including server credentials and API keys.

Encrypted in your browser with the passphrase you enter - Plembfin never sees or stores the plaintext backup.

The passphrase needs to be at least 12 characters. Losing it means the backup can't be decrypted - there's no recovery.

Remember passphrase

Scheduled backups run on the server with no browser open, so the server needs the passphrase saved.

Checked: the passphrase is stored in data/config.json so the schedule can run on its own.

Unchecked: the passphrase stays browser-only. Only "Back Up Now" works, and the schedule stays off.

Local Restore Guide

Disaster Recovery

Two backup types

Watch-history backups contain watched state, playstate, and resume progress. Use them to roll watch history back to a known point and push that state to Plex, Emby, and Jellyfin.

Plembfin backups contain the full Plembfin database data and saved settings. They are encrypted because they can include API keys and server credentials.

Watch-history restore

The selected watch-history backup becomes the source of truth:

  1. Wipes the local watch history, playstate and resume progress, and reloads them from the backup.
  2. Pushes that state out to every connected app (Plex, Emby, Jellyfin).
  3. Stamps a restore watermark so background sync does not re-import the previous app state.

While the restore is running, the cron sync and incoming webhooks are ignored, so nothing is written to watch history mid-restore. Watch dates are always preserved - an item already watched on an earlier date is never re-added as watched today.

Merge into existing state

Adds only the items the backup knows about to each app, without touching anything else. Fast. Any watched items the apps have that the backup never tracked are left as they are.

Replace existing state

Marks every currently-watched item on each app as unwatched, then re-applies only the backup's watched set, so each app ends up matching the backup exactly. Slower (it touches every watched item on every app), but this is a true restore.

Sync Tuning

Watched threshold, resume position, session TTL, outbound timeout, and fast local-network pacing

Sync Tuning Help

Understanding the Defaults
What This Controls

These values decide when a play counts as watched and how sync behaves.

Every field is optional. Leave one blank to keep the built-in default (or a matching environment variable, if one is set on the server).

Fields

Watched Threshold: playback progress percentage at which a play counts as watched. Default 90%.

Minimum Resume Position: playback position, in seconds, below which a stopped play is too short to save as a resume point. Default 60s.

Active Session TTL: how long a "now playing" session is kept without an update before it's considered stale. Default 5 minutes.

Outbound Request Timeout: how long Plembfin waits for a response from Plex, Emby, or Jellyfin before giving up. Default 10 seconds.

Fast Local-Network Sync: off by default. When enabled, Force Sync, Full Sync Watchstates, and other bulk sync operations send more concurrent requests with shorter gaps between them, finishing much faster. Only turn this on when Plex, Emby, and Jellyfin are all self-hosted on the same trusted local network as Plembfin.

Sync Issues Help

                        Understanding Issues
                      


                      

                        What are Sync Issues?
                        

                          This section shows any problems with propagating watched states between your media servers. Click on any issue to view detailed telemetry about what went wrong.
                        

                      


                      

                        Issue Categories
                        

                          Missing Dispatch Telemetry: No logging data recorded. These likely synced successfully but the logs are missing. Safe to clear.
                        

                        

                          Plex Match Issues: Plex couldn't find the media item. Check Plex metadata and external IDs.
                        

                        

                          Emby/Jellyfin Match Issues: Plex found it but Emby/Jellyfin couldn't. Check their metadata and IDs.
                        

                        

                          Unresolved Sync Issues: Other sync problems detected. Click to view telemetry for error details.
                        

                      


                      


                      

                        How to Fix
                        

                          Click "Retry" on an issue to re-attempt the sync and see detailed error messages. Click "Fix" to manually adjust the match if the item wasn't found.
                        

                      


                      

                        Refresh Issues
                        

                          Click "Refresh" in the Sync Issues header to immediately reload unresolved sync issues and match reports.
